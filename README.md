# KOL 智能筛选

面向飞书多维表格“达人总表”的侧边栏筛选插件。输入自然语言后，插件会读取当前视图并返回符合条件的达人；点击结果可打开记录详情。

筛选结果支持多选；每个已选择达人会单独显示选择理由输入框。生成的新表（名称格式为“达人筛选_日期_时间”）会逐行保存对应理由，并自动复制生成当时的报价、CPM、合作类型、账号/视频链接、推荐信息、粉丝数和平均播放量，同时保留对原达人记录的关联。未点击“生成新表”时不会创建任何结果表。

## 已支持的表达

- “头部”：明确定义为粉丝数不少于 100 万。
- “合作过”：是否合作过等于“是”。
- “英语”：语言等于“英语”。
- “欧美地区”：匹配欧美及主要英语市场。
- “杂食类游戏”：内容类型等于“泛游戏/游戏娱乐”。
- “整片 / Dedicated”：合作类型包含 Dedicated、整片或专属。
- “贴片 / Integrated / Integration”：合作类型包含 Integrated、Integration、贴片或植入。
- “Rise of Kingdom / 万国觉醒 / ROK”：综合内容类型、推荐标签与推荐理由打分。泛游戏/攻略评测、优先推荐/推荐以及 ROK、SLG、策略、手游等理由关键词加分；Minecraft/Roblox、宝可梦/任天堂、谨慎合作及不匹配理由关键词减分。达到 2 分才展示，并按得分优先排序。
- “粉丝数超过 1m / 1,000 / 100 万”：按粉丝数字段筛选，支持千分位及 k、m、w、万、亿。
- “播放量至少 100 万”：按近 30 天平均播放量筛选，支持相同数字单位。
- 其他词语：在当前参与筛选字段中执行包含搜索。

## 适配字段

当前版本要求数据表包含以下字段：

达人姓名、是否合作过、语言、内容类型、合作类型、粉丝数、近30天平均播放量、所属地区、推荐标签、推荐理由

## 本地开发

    npm install
    npm run dev

在多维表格插件开发配置中填入 Vite 提供的本地地址进行调试。

## 构建

    npm run build

生产文件输出到 dist。按飞书多维表格插件发布页面的要求上传 dist 构建产物或配置托管地址。

## 当前边界

- 插件从当前视图读取达人；只有多选并点击“生成新表”时才创建结果表，不修改达人总表已有记录。
- “适合 ROK”是根据内容类型进行的规则推断，不表示达人历史上实际推广过 ROK。
- 当前版本采用本地确定性规则，不会把表格数据发送给外部大模型。
